# MILESTONES — כפל בכיף

מבוסס על PRD.md, ARCHITECTURE.md ו־DESIGN.md ועל נכסי העיצוב שאליהם מפנה DESIGN.md. אבני הדרך מסודרות לפי תלויות, ללא לוחות זמנים. המסמך מתכנן את הפיתוח ואינו מעיד שהמוצר כבר מומש או נבדק.

## Development Execution Rules — כללי ביצוע ל־AI המפתח

1. יש לפתח את ה־Milestones לפי הסדר המוגדר במסמך.
2. לאחר השלמת כל Milestone יש לעצור את הפיתוח ולהציג למשתמש את התוצר שהושלם ואת תוצאות הבדיקות מול כל סעיף ב־Definition of Done.
3. אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש. היעדר תגובה אינו אישור.
4. יש להציג קישור או דרך פתיחה לתוצר, סיכום היכולות שהושלמו, הבדיקות שבוצעו ותוצאותיהן, וכן בדיקות שלא בוצעו וחסימות שנותרו. אין לסמן תנאי כעובר בלי ראיה.
5. כשל בתנאי השלמה מטופל בתוך ה־Milestone הנוכחי. לאחר תיקונו מציגים מחדש את התוצאות הרלוונטיות לפני מעבר.
6. בסיום כל אבן דרך שומרים את הקוד והבדיקות ב־Git עם Commit מזוהה. אין לשנות דרישות מוצר או להוסיף יכולות כדי להשלים אבן דרך.
7. אישור על מסמך זה אינו אישור גורף להתקדם בין אבני הדרך. כל מעבר מחייב אישור נפרד בהתאם לכללים לעיל.

## מסגרת הפיתוח והתלויות

| Milestone | יכולת או תוצר מרכזי | תלות |
| --- | --- | --- |
| M1 | בסיס אפליקציה רץ עם ניווט ושלד עיצובי | ללא |
| M2 | יצירה ובחירה של פרופילים מקומיים ומסך אודות מלא | M1 |
| M3 | תרגול מלא עם משוב ושמירת תוצאות נכונה | M2 |
| M4 | צפייה בהתקדמות אמיתית לכל פרופיל | M3 |
| M5 | התקנת PWA ושימוש מלא ללא אינטרנט | M4 |
| M6 | פריסה אוטומטית ובדיקת המוצר ב־GitHub Pages | M5 |

M1 הוא תנאי מקדים טכני מצומצם. M2–M5 מממשים יכולות משתמש מקצה לקצה; M6 מאמת את המוצר השלם בסביבת ההפצה.

**סביבות ונתונים:** לפי ARCHITECTURE.md אין Backend או Cloud Database. Development משתמש ב־localhost ו־Production בכתובת Pages, וכל Origin מחזיק IndexedDB נפרד. אין להקים פרויקטי Supabase או Database בענן. שינויי Schema מקומיים נבדקים בפיתוח לפני הפצה; הם רצים במכשירי המשתמשים עם פתיחת הגרסה החדשה, ולא כפעולת Database מרכזית ב־Production.

## M1 — בסיס אפליקציה עובד וניווט ✅

**מטרה:** להקים בסיס טכני ועיצובי שניתן להריץ ולבדוק לפני הוספת הנתונים והתרגול.

### מה יש לממש

- React, TypeScript strict, Vite, CSS Modules ו־Node.js 24 בהתאם לארכיטקטורה; גרסאות Stable תואמות ו־package-lock.json.
- Git Repository ב־GitHub, בלי שינוי נראות של Repository קיים. הגדרת GitHub Pages והפרסום עצמו נכללים ב־M6.
- App Shell ושלושת ה־Hash Routes בלבד: בית, לימוד ואודות.
- Bottom Navigation עקבי והדגשת הפריט הפעיל, לרבות Back ו־Refresh.
- Design Tokens מה־DESIGN: צבעים, טיפוגרפיה, מרווחים, קווי מתאר ופינות. שילוב גופנים מקומיים ורכיבי בסיס לשדות ולכפתורים.
- תצוגת מובייל ב־RTL ובידוד LTR למתמטיקה. התוכן העסקי טרם הושלם; אין להציג נתוני התקדמות פיקטיביים כנתוני משתמש.
- תשתית Vitest ו־Playwright עם בדיקת ניווט בסיסית ובדיקת TypeScript ו־Build.

### תוצר מצופה

אפליקציה מקומית רצה עם שלד המסכים והשפה העיצובית, ניווט עובד ו־Build תקין.

### Definition of Done

- התקנה באמצעות npm ci, בדיקת TypeScript, בדיקת ניווט ו־Production Build מסתיימות בהצלחה.
- שלושת מסלולי הניווט עובדים; Route לא מוכר מפנה לבית. מסך לימוד ללא פרופיל פעיל מפנה לבית.
- תוויות הניווט בעברית ובסדר התואם ל־DESIGN; הפריט הפעיל נכון.
- ברוחב מובייל מייצג הטקסט קריא, התוכן אינו נחתך והניווט אינו מכסה אותו.
- אין מסכים נוספים, שירותי ענן או נתוני ילדים ב־Repository.
- מוצגים למשתמש התוצר, מגבלות השלד ותוצאות הבדיקות; הפיתוח נעצר לאישור.

## M2 — פרופיל מקומי וכניסה לחוויה ✅

**מטרה:** לאפשר לילד ליצור ולבחור את הפרופיל שלו, ולהכיר את האפליקציה דרך מסך האודות.

### מה יש לממש

- מסך הבית לפי ה־DESIGN: מותג, Hero, כרטיסי פרופילים, טופס כינוי ואווטאר וכפתור כניסה ללימוד.
- אחסון Profile ב־IndexedDB באמצעות Dexie ושכבת Persistence; בחירה לפי id ולא לפי כינוי.
- Schema Version ראשוני עם טבלת הפרופילים; הגדרת מנגנון Version Upgrades ללא מחיקה אוטומטית.
- Validation לכינוי ריק ולאווטאר שלא נבחר, וטיפול בכשל כתיבה ללא חיווי שמירה כוזב.
- פרופיל פעיל בזיכרון והצגת הכינוי והאווטאר במסך הלימוד; מעבר אליו דרך הבית.
- מסך אודות מלא: טבלת לוח הכפל (טבלת HTML ולא תמונה), ההסבר והכפתור „חזרה לבית”.
- שילוב האיורים מתיקיית `assets` (איור הבית, רקע הכותרת ושלושת האווטארים) כנכסים מקומיים מכווצים; אין חשבונות או תמונות ילדים שהועלו.

### תוצר מצופה

ילד יכול ליצור פרופיל, לזהות אותו בביקור הבא, לבחור בו ולהיכנס למסך הלימוד; מסך האודות זמין ומעוצב. תרגול יתווסף ב־M3.

### Definition of Done

- יצירת פרופיל תקין ובחירתו עובדות מקצה לקצה; קלט חסר אינו יוצר רשומה.
- שני פרופילים נשמרים לאחר Refresh וסגירה ופתיחה מחדש. כינויים זהים אינם גורמים למיזוג זהויות.
- מסך ללא פרופילים מאפשר יצירה, וכניסה ישירה ללימוד ללא בחירה מחזירה לבית.
- כשל IndexedDB מוצג בבירור ואינו מוצג כהצלחת יצירה.
- יצירת Schema נבדקה על Database ריק; כל Migration שנוסף נבדק על נתוני דוגמה בפיתוח ללא אובדן נתונים.
- כל מכפלות לוח הכפל 1–10 בטבלת האודות נבדקו, והאיורים נטענים מקומית.
- מסכי הבית והאודות נבדקו מול ה־DESIGN וה־Mockups, לרבות סדר הרכיבים, RTL וגלילה.
- התוצר והבדיקות מוצגים למשתמש והפיתוח נעצר לאישור.

## M3 — תרגול מקצה לקצה ושמירת תוצאות ✅

**מטרה:** לאפשר לילד לפתור תרגילים עם משוב ורמז, תוך רישום אמין של התוצאות בפרופיל שלו.

### מה יש לממש

- שני מצבי התרגול: אקראי ולפי כפולה 1–10, עם Select פעיל רק במצב המתאים.
- תרגיל אחד, שדה תשובה וכפתור „בדיקה”; Domain מתמטי עצמאי בהתאם לארכיטקטורה.
- Validation לשלמים 1–100, הודעת הצלחה, עידוד ורמז חיבור חוזר במקרה טעות.
- מעבר לתרגיל חדש רק לאחר הצלחה ולחיצה על „לתרגיל הבא”.
- טבלת ExerciseResult והאינדקסים; שמירת ניסיון ראשון, יום מקומי, מונה ניסיונות ומצב פתרון.
- Transactions, submissionKey, revision ונעילת פעולות בזמן כתיבה למניעת כפילויות ושיוך שגוי.
- טיפול בכשל שמירה לפי הארכיטקטורה: המשוב אינו מציג תוצאה כאילו נשמרה, ואפשר להמשיך לתרגל בזיכרון.
- החלפת פרופיל או סוג תרגול ללא מחיקת תוצאות שכבר נרשמו.
- אזור ההתקדמות נשאר במסך הלימוד; הגרף והסיכום המחושבים יושלמו ב־M4.

### תוצר מצופה

תרגול מלא עובד לשני מצבי הבחירה. תוצאות אמת נשמרות בנפרד לכל פרופיל ומוכנות לשימוש במדדי ההתקדמות.

### Definition of Done

- בכל מצב נוצרים רק גורמים 1–10; בחירת כפולה מקבעת את הגורם המתאים.
- טעות משאירה אותו תרגיל ומציגה רמז נכון ללא חשיפת התוצאה, כולל תרגילים שאחד מגורמיהם הוא 1 (חיבור חוזר של 1). הצלחה מציגה את הודעת ה־PRD ומאפשרת המשך ידני בלבד.
- שדה ריק, מספר מחוץ לטווח או קלט לא תקין אינם נספרים כניסיון.
- תרחיש טעות ואז הצלחה שומר firstAttemptCorrect=false, מגדיל ניסיונות כנדרש ומסמן solved=true.
- בדיקת אותו ערך ללא בדיקה ביניים של ערך אחר, לחיצות מהירות ו־Retry של אותה כתיבה אינם יוצרים ספירה כפולה.
- תרגיל שנבדק ואז ננטש נשאר שמור; תרגיל שלא נבדק אינו יוצר רשומת תוצאה.
- תאריך הבדיקה הראשונה אינו משתנה בתיקון אחרי חצות. Refresh שומר את התוצאות ואינו מחייב שחזור תרגיל פתוח.
- החלפת פרופיל, השלמת כתיבה אסינכרונית והתנגשות כתיבות אינן מעבירות או מכפילות תוצאות.
- כשל כתיבה מדומה אינו מעדכן נתונים כאילו נשמרו.
- ה־Migration מ־Schema של M2 מורץ ונבדק בפיתוח ושומר פרופילים קיימים.
- בדיקות Domain וזרימת דפדפן עוברות; המשוב והתרגיל נבדקו חזותית בעברית.
- התוצר והבדיקות מוצגים למשתמש והפיתוח נעצר לאישור.

## M4 — התקדמות אישית המבוססת על תוצאות אמת ✅

**מטרה:** לאפשר לילד לראות את אחוז ההצלחה בניסיון הראשון ואת המגמה לאורך ימי התרגול.

### מה יש לממש

- Aggregation של ExerciseResult לפי profileId ויום הבדיקה הראשונה, ללא שמירת DailyStats כפול.
- גרף SVG וסיכום יומי במסך הלימוד לפי ה־DESIGN; ללא מסך התקדמות נוסף.
- ציר אחוזים 0%–100%, תאריכים כרונולוגיים, קו ונקודות Cyan וסיכום טקסטואלי קריא; עד 7 ימי התרגול האחרונים.
- מצבי אין נתונים ויום תרגול אחד לפי ה־PRD.
- רענון ההתקדמות לאחר שמירה מוצלחת והחלפת נתוני התצוגה בעת בחירת פרופיל אחר.

### תוצר מצופה

מסך הלימוד מציג התקדמות אמיתית, המבודדת לכל ילד ומתעדכנת בעקבות התרגול.

### Definition of Done

- עבור 10 תרגילים שנבדקו ומתוכם 8 נכונים בניסיון הראשון, הסיכום מציג 10, 8 ו־80%.
- טעות שתוקנה אינה הופכת להצלחה בניסיון הראשון; תרגיל שננטש לאחר טעות נכלל במכנה.
- ניסיונות חוזרים באותו תרגיל אינם מגדילים את מספר התרגילים. הגרלה חדשה עם אותם גורמים נספרת כמופע נפרד.
- יום ללא תרגול אינו מוצג כ־0%; במכנה אפס אין חלוקה באפס או נתון אחוזי מטעה.
- נתון יחיד מוצג בלי לטעון למגמת השתפרות.
- כשיש יותר מ־7 ימי תרגול, הגרף מציג את 7 האחרונים בלבד, והנתונים הישנים נשארים שמורים.
- בדיקות חצות, תאריך מקומי ושינוי אזור זמן שומרות על השיוך המקורי.
- הפרופילים אינם משתפים נתונים; לאחר סגירה ופתיחה מתקבלת אותה התקדמות מרשומות שמורות.
- נתוני הדוגמה ב־Mockups אינם Hard-coded במוצר. שגיאת שמירה אינה מתווספת לגרף כנתון שמור.
- הגרף, הסיכום והתרגיל קריאים במובייל ללא כיסוי על ידי הניווט; בדיקות החישוב והדפדפן עוברות.
- אם השתנה Schema, ה־Migration נבדק בפיתוח על נתונים קיימים. אם לא השתנה, מדווח שאין Migration נדרש.
- התוצר והבדיקות מוצגים למשתמש והפיתוח נעצר לאישור.

## M5 — PWA מלאה לשימוש ללא אינטרנט ✅

**מטרה:** לאפשר התקנה ושימוש בכל היכולות גם ללא חיבור לרשת, לאחר הכנה ראשונית.

### מה יש לממש

- Manifest, אייקונים ו־Service Worker באמצעות vite-plugin-pwa ו־Workbox generateSW.
- Precache לכל המסכים והנכסים, לרבות תמונות, אווטארים וגופנים מקומיים.
- start_url, id, scope ו־Base Path עקביים עם תצורת הפריסה.
- חיווי מוכנות רק לאחר השלמת ההכנה בפועל, וטיפול בהכנה חלקית.
- מחזור עדכון במצב prompt ללא Reload כפוי במהלך תרגול, בהתאם לארכיטקטורה.
- ניקוי Cache המוגבל לאפליקציה, תוך שימור IndexedDB.
- הוספת השורה במסך האודות שממליצה למשתמשי אייפון להוסיף את האפליקציה למסך הבית, לפי PRD (F5) ו־DESIGN.
- אימות על Production Build מקומי; בדיקות התקנה פיזיות בכתובת HTTPS הציבורית מושלמות ב־M6.

### תוצר מצופה

תוצר PWA עם נכסים זמינים מקומית, תרגול ונתונים העובדים ב־Offline ומנגנון עדכון שאינו קוטע שימוש.

### Definition of Done

- Manifest והאייקונים תקינים ו־Service Worker פועל ב־Scope הנכון.
- לאחר הכנה מלאה, ניתוק הרשת ו־Reload מאפשרים פתיחת שלושת המסכים, יצירת פרופיל, תרגול, שמירה וצפייה בהתקדמות.
- אין תלות ב־CDN, Fonts או API חיצוניים בזמן שימוש.
- מוכנות Offline אינה מוצגת כשה־Precache נכשל או טרם הסתיים.
- הכנה חלקית מציגה הודעה מתאימה כאשר App Shell זמין. בכניסה ראשונה אי פעם ללא רשת מתועדת מגבלת הדפדפן לפי ARCHITECTURE.md.
- פריסת שתי גרסאות על שרת הבדיקה אינה גורמת ל־Reload במהלך תרגיל; אחרי סגירת החלונות ופתיחה מחדש נטענת הגרסה החדשה והתוצאות נשמרות.
- כשל אחסון ועדכון Schema שנדרש נבדקו ללא מחיקת נתוני משתמש; Rollback אינו מסתמך על Downgrade של IndexedDB.
- מסך האודות מציג את ההמלצה למשתמשי אייפון בנוסח שב־DESIGN, מיושרת לימין וללא חיתוך במובייל.
- בדיקות Playwright ל־Offline ולמחזור העדכון עוברות על Build, ולא רק על Vite Development Server.
- התוצר והבדיקות מוצגים למשתמש והפיתוח נעצר לאישור.

## M6 — מוצר מפורסם ופריסה אוטומטית

**מטרה:** להעמיד את המוצר השלם בכתובת GitHub Pages ולהבטיח שעדכוני קוד נבדקים ומתפרסמים אוטומטית.

### מה יש לממש

- הפעלת Pages עם Source מסוג GitHub Actions והגדרת Base Path ל־Repository בפועל.
- Workflow לבדיקות ב־Pull Requests ו־Build/Deployment בעקבות Push ל־main, בהתאם לארכיטקטורה.
- TypeScript, Vitest, Playwright ו־Production Build לפני פרסום; הרשאות מינימליות ו־Concurrency לפריסה.
- אימות הנתיבים, הנכסים, Hash Routes, Manifest ו־Service Worker ב־HTTPS הציבורי.
- בדיקת התקנה ושימוש ב־Chrome ב־Android וב־Safari ב־iOS, כולל בדיקות במכשירים אמיתיים.
- בדיקת Regression כוללת לעיצוב, RTL, פרופילים, תרגול, התקדמות ושמירת נתונים.
- זיהוי Commit המפורסם ותיעוד דרך שחזור קוד התואמת ל־Schema המקומי.

### תוצר מצופה

אפליקציה זמינה ב־GitHub Pages, ניתנת להתקנה במכשירים הנתמכים ופועלת ללא אינטרנט לאחר הכנה. עדכון ל־main עובר בדיקות ומתפרסם ללא העלאה ידנית של קבצים.

### Definition of Done

- כתובת האתר נפתחת ב־HTTPS; שלושת המסכים והנכסים נטענים גם תחת נתיב Project Pages ו־Refresh.
- ריצת CI/CD אמיתית מוכיחה ש־Push ל־main בונה ומפרסם; Pull Request אינו מפרסם ל־Production.
- בדיקה או Build שנכשלו חוסמים Deployment ואינם מחליפים את הגרסה הפעילה.
- Manifest, start_url, scope וה־Service Worker עובדים מהכתובת הציבורית, ללא תלות בהגדרות localhost.
- במכשירי Android ו־iOS אמיתיים נבדקו התקנה, פתיחה לאחר התקנה, Offline ופתיחה חוזרת עם נתונים שמורים. אין להסיק שיתוף נתונים בין דפדפן ל־PWA אם אינו נתמך.
- תרחיש מלא עובר: יצירת שני פרופילים, תרגול בשני המצבים, טעות ורמז, הצלחה והמשך ידני, התקדמות נפרדת, סגירה ופתיחה.
- עדכון גרסה בכתובת הציבורית אינו קוטע תרגיל או מוחק נתונים.
- כל שינוי Schema הכלול בפרסום נבדק קודם בפיתוח; בעת פתיחת הגרסה החדשה נבדק השדרוג המקומי עם נתוני דוגמה. אין פקודת Migration על מסד Production מרכזי.
- העיצוב נבדק מול DESIGN.md והתמונות: שלושה מסכים בלבד, סדר רכיבים תואם, טקסט ללא חיתוך, גלילה תקינה, Focus, Labels ומשוב קריא.
- אין נתוני ילדים, סודות או מפתחות גישה בקוד או ב־CI Logs; אין הוספת שירותים חיצוניים שאינם נדרשים.
- למשתמש מוצגים כתובת המוצר, Commit, תוצאות כל הבדיקות ומגבלות ידועות. בדיקת מכשיר שלא בוצעה מדווחת כחסרה ואינה מסומנת כעוברת.
- הפיתוח נעצר לקבלת אישור המשתמש על התוצר הסופי.

## מדיניות לשינויים אחרי הפריסה

לאחר M6 כל שינוי ממשיך באותה מדיניות עצירה ואישור, במסגרת Milestone מאושר. שינוי Schema נבדק קודם בפיתוח עם נתוני גרסה קודמת; גרסת הקוד נפרסת רק לאחר הצלחת בדיקות התאימות. ה־Migration עצמו רץ מקומית אצל כל משתמש עם פתיחת הגרסה. אין למחוק IndexedDB כדי לפתור שגיאת שדרוג, ואין לפרסם Rollback שאינו תואם ל־Schema שכבר הופץ.
